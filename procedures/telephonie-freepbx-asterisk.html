1 Prérequis

Pour la réalisation du TP, il était nécessaire d'installer un serveur en machine virtuelle avec 4 Go de RAM et une IP fixe : 172.23.200.108/16.

  • 2 téléphones physiques.
  • Un téléphone virtuel via Linphone, à configurer par la suite.

Deux services devaient être désactivés :

  • Fail2ban
  • Firewalld

Identifiants générés par l'installation : sangoma:vsc4oJX55U57+Xpb

bash
# Service fail2ban
sudo systemctl stop fail2ban.service
sudo systemctl disable fail2ban.service

# Service firewalld
sudo systemctl stop firewalld.service
sudo systemctl disable firewall.service

Le protocole SIP/SDP envoie une requête INVITE à notre serveur pour établir une session de communication. Notre serveur répond par un ACK pour confirmer la requête et autoriser l'échange.

b. Décrochage de l'appel

L'image ci-dessous a été capturée lors du décrochage :

On peut voir 2 protocoles supplémentaires :

  • STUN (Simple Traversal of UDP through NATs) : le softphone envoie une requête au serveur STUN pour obtenir son adresse IP publique. Le serveur répond, ce qui permet au client de configurer sa session de communication.

D - Scénario d'attaque

Un attaquant pourrait enregistrer un message audio à l'aide d'un logiciel comme Audacity, puis déposer le fichier .wav dans le dossier correspondant. Le format doit cependant correspondre aux propriétés des autres enregistrements sur le serveur :

[ Capture à insérer — propriétés du fichier ]image (61).png (réutilisée)

L'extension et les caractéristiques du fichier doivent être identiques en termes de fréquence et de bit — ici 16 bits et une fréquence de 8000 Hz.

Sur le poste 1010, le fichier audio malveillant a donc été injecté. L'utilisateur est désormais capable d'écouter le message sur sa boîte vocale en consultant sa messagerie :

[ Capture à insérer — message injecté écouté ]image (64).png
⚡
Un attaquant doit au préalable avoir un accès root sur le serveur pour effectuer cette attaque.

7 Configurer un message d'alerte

Pour configurer une alerte diffusée automatiquement sur toutes les extensions configurées, aller dans Applications → Téléavertissement et intercom :

[ Capture à insérer ]image (69).png

Les paramètres importants à renseigner sont :

  • Téléavertissement du poste : 1015, permettant de composer le numéro pour la diffusion.
  • Une description.
  • La liste des dispositifs recevant l'alerte (ici les 3 postes).
  • Une tonalité d'alerte préconfigurée ou personnalisée.
  • Forcer même si le téléphone est occupé.

11 Réalisation du Trunk SIP

Aller dans l'onglet Connectivity → Trunks :

[ Capture à insérer ]image (88).png

Remplir les champs suivants :

  1. Trunk Name
  2. Outbound CallerID : permet d'afficher le nom de celui qui appelle sur le poste distant.
  3. CID Options : autoriser tous les CID.
  4. Maximum channels : 10, pour 10 communications simultanées.
[ Capture à insérer ]image (89).png

Aller dans l'onglet pjsip Settings :

[ Capture à insérer ]image (90).png
  1. Désactiver l'authentification pour les tests, afin de simplifier la configuration.
  2. SIP Server : serveur distant à joindre.
  3. SIP Server Port : 3654.
  4. Context : laisser par défaut.
  5. Transport : UDP.

✓ Points d'attention & retour d'expérience

→
Le format exact des fichiers audio (fréquence, bits) doit correspondre à celui des enregistrements existants sur le serveur pour qu'un fichier déposé manuellement dans une boîte vocale soit lisible — un bon exemple concret de ce qu'un accès root permettrait à un attaquant.
→
Changer le port SIP par défaut (5060) est une mesure simple mais efficace pour réduire la surface d'attaque exposée sur un serveur de téléphonie accessible depuis l'extérieur.
→
L'analyse Wireshark permet de bien visualiser le cycle de vie SIP (INVITE/ACK), l'établissement du flux média (RTP/STUN) et la fin de session (BYE) — utile pour diagnostiquer des problèmes de qualité d'appel ou de NAT.
